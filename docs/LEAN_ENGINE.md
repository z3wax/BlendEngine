# Lean game editor distribution

BlendEngine's source checkout contains Blender's C/C++ code, generated game
exports, repeated `.blend` files, and a downloaded city-model cache. Those files
are useful development inputs, but they do not belong in an editor-addon
distribution. The lean packager creates a separate ZIP without deleting source
or modifying any materials, textures, mesh data, or graphics settings.

## Repository cleanup

The source checkout also removes 172 obsolete generated text files under
`builds/`: copied desktop launchers, duplicated JSON game/config manifests,
browser players, and old Android/iOS WebView scaffolds. This removes 9,933,540
logical bytes from the checkout. All 31 existing graphics files and backups
(362,354,669 bytes) remain at their original paths, with their bytes unchanged.
Engine source and licenses are retained. Ignore rules keep future generated
platform wrappers out of commits. See [retained source scenes](../builds/README.md).

This cleanup is separate from the lean ZIP size comparison. The maintained
native Android source is `native/android_game`, using Godot C++ and OpenGL ES.

## Build the small addon package

From the repository root:

```bash
python3 tools/blendengine/package_lean.py --output ../artifacts/BlendEngine-lean-addon.zip
```

The tool requires both the portable Last Signal character and the user-provided
`assets/brand/logo.jpg`. A missing required asset fails packaging instead of
silently relying on a development machine's old exported scenes. Re-run with
`--force` to replace the same artifact. Without `--output`, the command only
prints the manifest.

Install the ZIP in Blender 3.6's **Preferences → Add-ons → Install**, then enable
BlendEngine. The host Blender executable is a separate prerequisite.

For the native game project and its asset-export tools as well, create the SDK
profile. Its source-relative layout can be extracted into a separate workspace:

```bash
python3 tools/blendengine/package_lean.py --profile sdk \
  --output ../artifacts/BlendEngine-lean-sdk.zip
```

The SDK includes `native/android_game`, its GLB/game assets and Godot scripts,
the Blender addon, the scene asset exporter, Android build/QA tools, and the
Android/story documentation with its reference images and reports. It excludes `.godot` imports,
Gradle caches, Android build directories, APK/AAB outputs, and signing keys.
The GLB embeds its material textures; intermediate bake PNGs are omitted to
avoid shipping those same pixels twice. The exporter can regenerate them.
Godot, export templates, Blender and the Android SDK are separate prerequisites.
Its required `assets/last_signal.glb` must be generated by the asset exporter
before packaging; a missing playable scene fails SDK creation.

An addon installed in Blender's own directories needs the location of the
extracted SDK for native Android export. Set `BLENDENGINE_SOURCE_ROOT` to that
SDK directory before launching Blender. For example on Linux/macOS:

```bash
BLENDENGINE_SOURCE_ROOT=/absolute/path/to/BlendEngine-lean-sdk blender
```

On Windows, set the environment variable to the extracted SDK directory before
launching Blender. Keep `native/android_game/project.godot` and
`tools/blendengine/export_native_assets.py` at their SDK-relative paths.

| Included | Omitted from this distribution |
|---|---|
| Every BlendEngine Python editor, graphics, runtime, story and export module | Blender C/C++ source, libraries and build tools |
| Portable character, addon assets and brand artwork | Generated desktop, iOS, Android, browser and WebView game outputs |
| Native export templates, when present in the addon | `builds/model_cache`, scene duplicates, Python bytecode and backups |
| Upstream GPL, third-party license and copyright notices | Git metadata, screenshots, recordings and development test outputs |

The package contains `MANIFEST.json`; a `.manifest.json` sidecar also records the
archive's SHA-256 and compressed size. Each shipped file has an original source
path, byte count and SHA-256. Sorted entries, fixed ZIP timestamps and fixed
permissions make repeated packaging of the same input deterministic.

The size comparison uses logical source-file bytes, excludes `.git`, generated
root `dist/` releases and the current output ZIP/sidecar, and reports each
top-level directory separately.
It compares a development checkout with an addon distribution. It does **not**
measure a compiled editor's installed size, memory consumption, frame rate, or
APK size. A native game and its required game assets are separate artifacts.

## Optional game-focused desktop CMake profile

For a new desktop editor build, after installing Blender's normal development
dependencies:

```bash
cmake -S . -B ../blendengine-game-build \
  -C build_files/cmake/config/blendengine_game.cmake
cmake --build ../blendengine-game-build --parallel
```

This profile keeps Eevee, OpenColorIO, HDR/OpenEXR and WebP, Python editor tools,
Bullet, audio, IK, subdivision, exact booleans, glTF/Draco support and OpenVDB
volume assets. Cycles remains available for the native exporter's procedural
PBR texture baker. It disables standalone Cycles, OSL, offline CPU
compositing/denoising, Freestyle,
video codecs, camera tracking, fluid/ocean simulation, and selected film/document
interchange formats. Other game asset importers and Blender's real-time
compositor remain available. Existing game-scene quality settings are preserved.

This is a game-focused feature set. Scenes that depend on disabled offline
features should use a normal Blender build. Option names have been checked
against this source tree. CMake is unavailable in the current environment;
configure and compile the profile on each release target before claiming a
smaller compiled editor. This profile requires the full source checkout, which
is not bundled into the lean SDK.

Android export uses the separate native Godot runtime. This desktop profile does
not produce an APK. Regenerating procedural texture bakes uses Cycles in a full
Blender build; the native game uses the baked textures without Cycles. Test the
resulting APK on Android before uploading any changes or release artifacts to
GitHub.
